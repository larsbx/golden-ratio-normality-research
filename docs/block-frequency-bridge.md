# From certified digit words to normality counts

The finite foundation binds a native digit word to the real number
α = (√5−1)/2 and certifies its overlapping pattern counts. This milestone
connects those counts to the exact function used in `NormalInBase`.
It supplies a universal identity and finite discrepancy certificates.
The asymptotic frequency estimate remains a separate research obligation.

## Exact theorem and conventions

Let b≥2, let w be a nonempty word of length k with every symbol below b,
and let L be any natural number. Write v_b(w) for its positional value,
reading the most significant digit first. The theorem is

\[
 \operatorname{Blocks.count}(w,\operatorname{actualDigits}(b,0,L))
 = C_{b,k,v_b(w)}\bigl(\max(0,L+1-k)\bigr),
\]

where

\[
 C_{b,k,j}(N)=\#\{0\le n<N:
   \lfloor b^{n+k}\alpha\rfloor-b^k\lfloor b^n\alpha\rfloor=j\}.
\]

`C` is exactly `GoldenNormality.occurrences`. The public declaration is
`GoldenNormality.count_actualDigits_eq_occurrences` in
[`FrequencyBridge.lean`](../GoldenNormality/FrequencyBridge.lean).
The subtraction in `L + 1 - k` is natural-number subtraction, truncated
at zero. Overlaps are included because every start advances by one symbol.

For k≥1, the corollary `count_actualDigits_prefix` gives exactly N starts
from a prefix of length N+k−1. This also covers N=0: k−1 digits have no
complete k-block. The general theorem additionally handles shorter prefixes,
including L=0. No supplied digit is extended beyond the certified word.

## Derivation

[`BlockNumerals.lean`](../GoldenNormality/BlockNumerals.lean) defines

\[
 v_b([])=0,\qquad
 v_b(d::r)=d\,b^{|r|}+v_b(r).
\]

An induction proves `wordValue_lt`: an alphabet word of length k has value
strictly below b^k. From this bound, equal values of two equal-length
alphabet words force their leading digits to agree; induction then forces
their tails to agree. This is `wordValue_injective`.

The existing block concatenation law identifies the positional evaluation
of an actual digit segment with its floor-difference block value:

\[
 v_b(d_n\ldots d_{n+k-1})
 =q_{n+k}-b^kq_n,
 \qquad q_n=\lfloor b^n\alpha\rfloor.
\]

The proof uses nonnegativity of actual digits when passing between natural
and integer values. The numeral identity itself holds at all natural b,
n, and k; the matching and frequency interfaces state b≥2, as required
by the normality target.

Separate take, drop, and window theorems preserve the digit segment's
starting position. For every complete window, fixed-length numeral
injectivity then identifies list equality with the block-value equality
tested by `occurrences`. Finally, starts with fewer than k remaining
symbols contribute zero to the list counter. Removing that zero tail
leaves precisely the first `L + 1 - k` starts. These arguments cover every
L and every nonempty alphabet word, independently of executable resource
bounds or the size of the current receipt fixtures.

## Source-bound finite certificates

`certified_occurrences_sound` consumes four substantive premises:

1. The base is at least two.
2. The pattern is nonempty and belongs to the base alphabet.
3. `DigitsAt b 0 text` proves that the supplied word consists of the actual
   first digits of α.
4. `Blocks.count pattern text = value` proves its exact consecutive count.

It concludes the exact `occurrences` equality at
`N = text.length + 1 - pattern.length`. The native receipt generator emits
this theorem for every histogram entry, including entries with count zero.
For each entry it also emits

\[
 \operatorname{Nat.dist}(b^k C_{b,k,j}(N),N)=D,
\]

with the numeral D checked by Lean after substituting the proved count.
Using `Nat.dist` retains negative deviations as absolute differences;
truncated subtraction would lose them. The universal declarations
`certified_discrepancy_eq` and `certified_discrepancy_bound` also transfer
any explicitly supplied finite discrepancy bound without changing its
scale or tolerance.

The producer and independent oracle still perform finite conformance checks.
The translator's output must compile as propositions about the mathematical
digit sequence. A separate module generated by
[`tools/receipt_contracts.py`](../tools/receipt_contracts.py) recomputes the
expected counts directly from the contract and independent oracle, without
reading the native receipt values or the main translator's source. Its
explicit types require every occurrence and discrepancy declaration to prove
the expected proposition. Merely preserving a receipt's name or replacing
its type with a weaker true proposition cannot satisfy this check. The
compiled audit includes these wrappers as well as the original receipts.

This does not establish a universal refinement theorem for the native
producer, BigZ operations, or either compiler.

## Counterexamples retained by the acceptance gate

The gate compiles and audits concrete counterexamples to stronger variants,
then checks that four corresponding invalid uses of the bridge are rejected.
The sources are generated by [`tools/bridge_controls.py`](../tools/bridge_controls.py).

| Necessary condition | Checked counterexample |
| --- | --- |
| Equal lengths in numeral injectivity | `[0,1]` and `[1]` have the same base-10 value but are different words. |
| Symbols below the base | `[0,10]` and `[1,0]` have equal lengths and equal base-10 values; the former is not a base-10 word. |
| Nonempty pattern | The list API assigns count zero to the empty pattern, while `occurrences 2 0 0 1 = 1`. |
| Complete-window start bound | `[1]` contains no complete `[1,0,0]` block, while the actual first three binary digits of α are `[1,0,0]`, so `occurrences 2 3 4 1 = 1`. |

A fifth rejection control supplies a weaker true theorem where an exact
discrepancy equality is required. This must fail with a type mismatch, so the
independent receipt checker cannot be satisfied by declaration names alone.

The contract adds native cases `(b,L,k)=(2,0,3)` and `(2,1,3)` to exercise
empty and nonempty prefixes shorter than k−1. These supplement the existing
empty width-one case and the decimal case with L=k−1. The additional case
`(2,3,3)` certifies the actual word `100` with exactly one complete start,
distinguishing `L+1−k` from the incorrect `L−k` at L=k. Larger samples are
unnecessary for checking these boundary identities.

## Replay and acceptance

With the pinned dependencies installed, run from the repository root:

```sh
python3 tools/verify.py --output build/block-frequency
```

The output directory must be new or empty. The full gate builds fresh
project proof objects, checks the explicit public theorem types, audits
every compiled declaration's transitive dependencies, builds the canonical
Mojo producers, checks their independent oracle, and compiles all generated
receipts and counterexample controls. It rejects timeouts, failed tools,
unexpected assumptions, and source changes during the run.

An acceptance report records its exact source revision and content hashes.
The claim ledger describes theorem scope; only the observed report records
whether a particular revision passed. Any committed evidence packet is an
evidence-only child of the accepted source revision.

## Remaining obligation

The new identity makes finite certificates and future estimates speak about
the same count. It does not provide the estimate required by `NormalInBase`:

\[
 \forall k\ge1\;\forall j<b^k\;\forall T\ge1\;
 \exists N_0\ge1\;\forall N\ge N_0:
 \quad |b^k C_{b,k,j}(N)-N|T\le N.
\]

For the binary automaton approach, the unresolved distribution problem is
still the output sequence along the particular inputs Z(2^n), including
all consecutive output blocks. A finite discrepancy equality, even at a
large N, supplies none of the eventual quantifiers in this statement.
